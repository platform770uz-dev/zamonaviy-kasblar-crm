## Правила
- Формы вакансий страницы в Make не добавлять: их уже принимает прямой вебхук, через Make заявки задвоятся (Make пишет в `meta_admin_leads`).
- Академия никогда не пишется в `meta_admin_leads`.
- Новую форму академии нужно добавить в `META_YBA_FORM_IDS` (секрет функции `meta-yba-webhook`) и в маршрутизацию `meta-admin-lead-ingest`, иначе лид не попадёт во вкладку академии.
- Вкладка «Blogerlik leadlari bolalar» нужна функциям приёма лидов, удалять и переименовывать её нельзя.
- Удаление вкладки CRM каскадно удаляет все её записи.

## Развёрнутые функции и список форм (с 31.10.2026)
- `meta-yba-webhook` v12: принимает только формы из `META_YBA_FORM_IDS` (по умолчанию `1657196732409379`).
- `meta-admin-lead-ingest` v20: формы академии (`1657196732409379` + `META_YBA_FORM_IDS`) идут во вкладку CRM, формы вакансий (`1116743630843921`, `1471428244799477` + `META_HR_FORM_IDS`) идут в `meta_admin_leads`, любая другая форма получает ответ 422.
- Хеш токена Make в публичный репозиторий не кладётся: в репозитории он читается из секрета `MAKE_TOKEN_SHA256`, а в развёрнутой функции задан как значение по умолчанию. При повторном развёртывании из репозитория задайте этот секрет или подставьте прежний хеш, иначе все запросы Make получат 401.
- `meta-admin-lead-ingest` v30 (26.11.2026): добавлена форма агента по продажам `1978722713097224` (константа `SALES_AGENT_FORM_ID`). По новой заявке функция сама шлёт руководителям из `tg_chatlar` короткое уведомление через `TELEGRAM_BOT_TOKEN`; повтор от Make второго уведомления не даёт. В Make эту форму нужно добавить в сценарий отдельно.
- `meta-admin-lead-ingest` v30: форма агента `1978722713097224` записана в маршрутизацию на случай отправки через Make, но эта форма приходит прямым вебхуком; в Make её не добавлять.

## Раздел CRM «Вакансии» (с 26.11.2026, бывшие «HR-лиды»)
- Показывает кандидатов из вкладки «Вакансии Facebook» и из `meta_admin_leads`; у вкладки «Вакансии Facebook» своего пункта меню больше нет.
- Папка = вакансия: название формы без служебных частей (`hrFolderTitle` в `app.js`: «Ishga ariza», месяц и год, «hajm», «-copy», скобки). Копии одной формы и одна вакансия из обоих источников попадают в одну папку. Формам старого пути (Make, сайт) подписи даёт `hrVacancies` по ID формы.
- Новая кампания получает папку сама: `meta-yba-webhook` (v34) регистрирует незнакомую форму с названием из Meta и пометкой «(авто)»; если Meta название не отдала — «Новая вакансия <ID> (авто)», а в `meta_webhook_debug` пишется `form_name_error`. Переименовать форму: `meta_lead_forms.name` и поле «Вакансия» её записей во вкладке.
- Внутри папки полки по этапам: Новые → Связались → Собеседование → Приняты → Отказ. Этап во вкладке хранится в «Holat» по-узбекски (Yangi, Bog‘lanildi, Suhbat, Qabul qilindi, Rad etildi), заметка — в «Заметка»; в `meta_admin_leads` — `pipeline_status` и `crm_note`.
- 26.11.2026 в объявлении агента форму «Sotuv agenti | Farg'ona | Ishga ariza | Nov 2026 | hajm» заменила копия «… | yosh»: без вопроса про русский язык, с вопросом «Necha yoshdasiz?» (18–20, 21–25, 26–30, 31–40, 41–50, 51 va undan katta). В CRM возраст 21–50 — ✓, остальные — ✕ (решение владельца). Предупреждение: Meta не разрешает собирать возраст в формах категории «Трудоустройство», форму могут отклонить. Новая форма попадает в ту же папку «Sotuv agenti · Farg'ona».
- Подписи вопросов и правила «подходит / уточнить / не подходит» — `hrQuestionRules`; для вопросов без правила «…olasizmi? / tayyormisiz? / bormi?» действует `hrGenericRule` («ha» — подходит, «yo‘q» — нет).
